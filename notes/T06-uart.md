## 一、自测（遮住答案先答一遍）

1. 115200 8N1 一帧多少位、多长时间？128 字节的 buffer 能缓冲多少毫秒？
2. `BRR = 0x271` 是怎么算出来的？USARTDIV 的整数部分和小数部分分别存在哪几位？
3. F1 的 `PLLSRC` 是置 0 还是置 1 选 HSE？配错的话芯片跑在多少 MHz、波特率变成多少？
4. `NVIC->ISER[1]` 里的 `[1]` 和 `bit5` 是怎么来的？为什么这里必须用 `|=` 而不是 `=`？
5. `RXNE`、`TXE`、`TC` 三个标志各表示什么？分别在什么场景下用？
6. `ORE` 什么时候置位？怎么清？为什么说"ORE=1 时 RXNE 必然=1"？
7. 中断里调 `HAL_Delay` 为什么会卡死？你这块板子上谁优先级高？
8. `TDR` 和 `RDR` 是同一个地址，硬件靠什么区分？

<details>
<summary>答案（点开对照）</summary>

1. **10 位**（1 起始 + 8 数据 + 1 停止），**86.8 µs**。128 × 86.8 µs = **11.1 ms**——这是字节背靠背连续到达的**最坏情况**，实际有间隔会更久。
2. `USARTDIV = 72 000 000 / (16 × 115200) = 39.0625`。整数 39 = `0x27` 存 **BRR[15:4]**，小数 `0.0625 × 16 = 1` 存 **BRR[3:0]**，合起来 `(39 << 4) | 1 = 0x271`。
3. **置 1 才是 HSE**（`RCC_PLLSOURCE_HSI_DIV2 = 0x0`、`RCC_PLLSOURCE_HSE = bit16`）。配错成 0 会选 HSI/2 = 4MHz，×9 = **36MHz**，波特率变成 **57600**（正好一半）。
4. USART1 是 **37 号中断**，`37 ÷ 32 = 1 余 5` → `ISER[1]` 的 bit5。ISER 一个寄存器管 32 个中断，用 `=` 会把同组的其他中断使能位**全部清 0**，以后加 SPI1(35)、USART2(38) 会莫名不响应。
5. `RXNE`(bit5)=RDR 里有数据可读；`TXE`(bit7)=**TDR 空了、可以写下一个**；`TC`(bit6)=连同移位寄存器都空了、整帧真的发完。连续发送用 TXE；要切 RS485 方向或进低功耗用 TC。
6. RXNE 仍为 1 时新数据想进 RDR → ORE 置位（**所以 ORE=1 ⟹ RXNE=1**）。清除靠"读 SR **后**读 DR"这条序列，少一步都不行。丢的是新来的字节，**RDR 里那个旧字节仍然有效**。
7. `HAL_Delay` 靠 `uwTick` 递增，`uwTick` 由 SysTick 中断加 1。SysTick 优先级 **15**（`TICK_INT_PRIORITY = 0x0F`），USART1 没设置 = 复位值 **0**，比 SysTick 高 → SysTick 抢不进来 → `uwTick` 不变 → `while` 永远等下去。
8. 靠**读写方向**：读 `DR` 取的是 RDR（收到的），写 `DR` 送到 TDR（要发的）。

</details>

## 二、一句话结论

> **串口不是"一根线传数据"，是两套独立硬件同时工作**：接收侧（RX → 接收移位寄存器 → RDR → 中断 → ringbuf）和发送侧（ringbuf → 主循环 → TDR → 发送移位寄存器 → TX）各有自己的缓冲和移位寄存器，所以能全双工。CPU 只负责在两端搬字节，中间的定时和移位全由硬件完成。

## 三、骨架（表格版）

### 3.1 五个寄存器各管什么

| 寄存器 | 作用 | 本包用到的位 |
| --- | --- | --- |
| `SR` | 状态，告诉 CPU "发生了什么" | bit7 TXE、bit6 TC、bit5 RXNE、bit3 ORE |
| `DR` | 数据，**读=RDR，写=TDR** | bit8:0 |
| `BRR` | 波特率 | bit15:4 尾数、bit3:0 小数 |
| `CR1` | 控制 | bit13 UE、bit5 RXNEIE、bit3 TE、bit2 RE |
| `CR3` | 控制 3 | bit0 EIE（只在 DMA 多缓冲下对 ORE/NE/FE 生效） |

### 3.2 中断要过两道门

```
USART 内部：CR1 bit5 (RXNEIE) = 1   →  允许 USART 发出中断请求
NVIC 层：  ISER[1] bit5 = 1         →  允许这个请求送到 CPU
启动文件：  .weak USART1_IRQHandler  →  你写同名函数就接管（没有注册、没有回调表）
```

**两道门缺一不可**。只开 CR1 不开 NVIC，中断永远进不来——这是上串口第一天最常漏的一步。

### 3.3 收发双通路（全双工的物理基础）

| | 通路 | 谁在动 |
| --- | --- | --- |
| 接收 | RX 引脚 → **接收**移位寄存器 → RDR → 中断 → ringbuf | 硬件逐位采样，收满才通知 |
| 发送 | ringbuf → 主循环 → TDR → **发送**移位寄存器 → TX 引脚 | CPU 只写 TDR，剩下硬件干 |

**双缓冲**：TDR 和发送移位寄存器是两级。写 DR 时若移位寄存器空，数据立刻搬过去、TDR 马上再空（TXE=1）；若移位寄存器忙，数据就留在 TDR 等。所以"发第 1 个字节的同时"可以把第 2 个写好排队，停止位一结束无缝接上。

### 3.4 HAL ↔ 寄存器对照

| 想做什么 | HAL 写法 | 寄存器等价 |
| --- | --- | --- |
| 开 GPIOA / USART1 时钟 | `__HAL_RCC_GPIOA_CLK_ENABLE()` | `RCC->APB2ENR` bit2 / bit14 |
| PA9 配复用推挽 | `HAL_GPIO_Init(..., AF_PP)` | `GPIOA->CRH` bits[7:4] = `0xB` |
| PA10 配上拉输入 | `HAL_GPIO_Init(..., PULLUP)` | `GPIOA->CRH` bits[11:8] = `0x8` + `ODR` bit10 = 1 |
| 设波特率 | `huart.Init.BaudRate = 115200` | `USART1->BRR = 0x271` |
| 使能串口 | `HAL_UART_Init()` | `CR1`: UE(13) + TE(3) + RE(2) |
| 开接收中断 | `HAL_UART_Receive_IT()` | `CR1` bit5 + `NVIC->ISER[1]` bit5 |
| 收到一个字节 | `HAL_UART_RxCpltCallback()` | `if (SR & RXNE) b = DR;` |
| 发一个字节 | `HAL_UART_Transmit()` | 等 `SR.TXE`，然后 `DR = b` |
| **重新武装接收** | **回调里再调一次 `HAL_UART_Receive_IT`** | **不需要——硬件每字节都会置 RXNE** |

最后一行是本包最重要的对照：**HAL 的"重新武装"是它自己的机制（每次只收 N 个，收完就停），寄存器版根本不需要**。这也是为什么寄存器版少一层、少一个坑。

## 四、我原来错在哪

> ⚠️ **修正 1**：原文「波特率 115200 是每秒发送 1 个 bit」——漏了数字。
> 正确：**每秒 115200 个 bit**，每个 bit 占 **8.68 µs**。后面的 86.8 µs 是对的，说明只是写漏了。

> ⚠️ **修正 2**：原文「`SR & (1<<7)` 是检查 TXE 发送数据寄存器为 1」——读起来像"寄存器里有数据"。
> 准确：**TXE=1 表示"发送数据寄存器空了"**，可以写下一个字节。名字里的 E 就是 Empty。

> ⚠️ **修正 3**：原文「一帧用 1 字节内存刚好可以」——说不通。
> 正确：一帧 10 bit 对应 **1 字节有效数据**；128 字节 buffer = 128 帧 = **11.1 ms** 的缓冲时间。

> ⚠️ **修正 4**：原文「AI 丢弃刚到达的字节，我的代码好像没有缓冲区满的保护」——**你的也有，而且和 AI 逐字相同**。
> `ringbuf_write` 满时 `return false` 且不写入 = 丢弃最新字节；AI 的 `RingBuffer_Put` 一模一样。**两边都是"丢了没人知道"**，区别只在没人检查返回值。
> AI 代码真正的不同在别处：`uint8_t buffer[256]` **内嵌在结构体里**（每实例自带 256 字节，不能共用），你的 `uint8_t *buf` 由外部传入（可共用、可变大小）。

> ⚠️ **修正 5**：原文「主循环用 while 进行阻塞，CPU 一直卡在这里」——那不是阻塞，是**轮询**（polling）。
> 阻塞 = 等事件时让出 CPU；轮询 = 反复问"好了没"。裸机没有调度器，没得让出，只能轮询。想省电在主循环末尾加 `__WFI()`。

> ⚠️ **补充**：docx 最后一句「DR 寄存器是一个过渡，是外部」没写完。

## 八、这包最值钱的三条

1. **`PLLSRC` 极性**：F1 里 bit16=1 才是 HSE，0 是 HSI/2。配错不报错，只是悄悄跑在 36MHz，波特率变 57600——**延时类代码发现不了（分子分母一起错），通信类必现**。
2. **`ORE` 的因果**：ORE 只在"RDR 还满着又来新字节"时置位，所以它必然伴随 RXNE=1；清除只认"读 SR + 读 DR"这一条序列。中文版手册第 541 页把 DR 印成了 CR，是翻译错误。
3. **双缓冲 + 全双工**：能同时收发不是因为一个寄存器干两件事，而是因为**有两套独立硬件**；TDR 和移位寄存器的两级结构，让"发当前字节"和"排队下一个字节"能并行。
