## 一、自测（遮住答案先答一遍）

1. `struct A { char a; int b; char c; }` 占几字节？填充在哪几个位置？
2. `get_packed(p) { return p->b; }` 和 `get_aligned(p) { return p->b; }` 的反汇编差在哪？为什么会差？
3. `_Static_assert` 在反汇编里有对应的指令吗？为什么？
4. 一段代码"没被生成指令"，通常是什么原因？要让它留下来，有哪三种办法？
5. 算栈还能用多少，该拿 `_estack` 减哪个符号？为什么不是减 `__bss_end__`？
6. `*(uint32_t *)0x00000001 = 5;` 执行后，为什么 CALL STACK 指向的是**下一行**而不是这一行？
7. `for (uint8_t i = 0; i <= 255; i++)` 为什么编译器说比较"恒为真"？这个警告属于 `-Wall` 还是 `-Wextra`？
8. `int x = INT_MAX;` 之后，为什么 `printf("%d", x + 1)` 打出 `-2147483648`，而 `(x + 1) > x` 却是 `1`？
9. 悬空指针和野指针的区别是什么？各自的现象是什么？

<details>
<summary>答案（点开对照）</summary>

1. **12 字节**。`a` 在 0，偏移 1–3 填充，`b` 在 4–7，`c` 在 8，偏移 9–11 填充（为了结构体整体按 4 对齐）。换顺序成 `{int b; char a; char c;}` → 8 字节，填充只剩 2 个。
2. `get_packed` 是 `ldr.w r0, [r0, #1]`（**宽指令**），`get_aligned` 是 `ldr r0, [r0, #0]`。差别来自 `packed` 让 `b` 落在偏移 **1**，是非对齐地址。
3. **没有**。`_Static_assert` 是编译期检查，通过了就什么都不生成；同理 `__attribute__` 也只是给编译器的声明。
4. 编译器认为它**对外界没有影响**（没有可观察的副作用）。三种办法：① 用 `volatile` 全局变量保存；② 写寄存器；③ 调用外部函数。
5. 减 **`end`**。`__bss_end__` 只是"最后一个变量结束"，后面还有链接脚本用 `. = ALIGN(8)` 补的填充；`end` 才是堆/栈区域的真实起点。
6. 因为写未映射地址是**不精确总线错误（imprecise bus fault）**：写请求发出后 CPU 不等响应就往下走，错误要到下一次总线事务才被报告，所以压栈的 PC 指向 `str` 的下一条指令。
7. `uint8_t` 最大就是 255，`i <= 255` 永远成立，循环停不下来。属于 **`-Wextra`**（`-Wall` 不开）。
8. 第一个是**硬件行为**：有符号溢出后绕回成最小值。第二个是**编译器的假设**：标准说"有符号溢出是 UB"，编译器就假设它不会发生，于是把 `x+1 > x` 直接折成常数 `1`，根本不去算。
9. **野指针**是从来没赋过值的指针，指向随机地址，一用就炸（烧完程序灯快闪）。**悬空指针**是曾经有效、但指向的对象已经没了（比如 `return &local;`），"看起来还能用"，读到的是别人的数据——更阴。

</details>

## 二、一句话结论

> **编译器只对"能观察到后果"的代码负责**：没有副作用就被删掉，有 UB 就按"不会发生"来推理，
> 而内存边界它一律不检查——所以栈多大、越界写到谁，只能自己算。

## 三、骨架（表格版）

**① 三个关键字**

| 名字 | 作用 | 关键点 |
| --- | --- | --- |
| `__attribute__((packed))` | 取消对齐，成员紧挨着 | `struct C` 从 12 变 **6**；代价是偏移 1 的非对齐访问 |
| `__attribute__((noinline))` | 取消内联 | 调试时能在 CALL STACK 里看到这个函数 |
| `__attribute__((used))` | 防止编译器在 `.o` 里删掉它 | 但链接器开了 `--gc-sections` 仍可能删 |
| `_Static_assert(expr, msg)` | 编译期断言（C11） | 成立什么都不做，不成立直接编译失败；**不产生指令** |
| `offsetof(struct A, b)` | 成员相对结构体起始的字节偏移 | 常和 `_Static_assert` 搭配，编译期校验布局 |

**② 对齐规则与实测**

| 结构体 | sizeof | 填充字节数 |
| --- | --- | --- |
| `A {char a; int b; char c;}` | 12 | 6 |
| `B {int b; char a; char c;}` | 8 | 2 |
| `C packed {char a; int b; char c;}` | 6 | 0 |

- 成员地址必须是**自身对齐值**的整数倍（不是笼统的"4 的倍数"）⚠️
- 结构体总大小必须是**最大成员对齐值**的整数倍 ⚠️

**③ 20KB RAM 怎么分**

| 段 | 内容 | 本工程实测 |
| --- | --- | --- |
| `.data` | 有初值的全局变量 | 从 `0x20000000` 起 |
| `.bss` | 初值为 0 / 未初始化的全局变量 | 紧跟 `.data` |
| `._user_heap_stack` | **链接期检查量**：512 B 堆 + 1024 B 栈 | 1540 B（含 4 B 对齐填充） |
| 剩下 | 堆和栈**共享**，从两头往中间长 | 约 18.8 KB |

- `_Min_Stack_Size = 0x400` 是**检查量，不是运行时边界**
- 真实可用栈 = `_estack − end` = `0x20005000 − 0x20000050` = **20400 B ≈ 19.9 KB**
- 为什么是 `0x50` 不是 `0x4C`：`._user_heap_stack` 开头有 `. = ALIGN(8)`，`0x4C` 补 4 字节到 `0x50`
- 越界不会报错，链接器只在**链接期**检查 `.data + .bss + 1540 ≤ 20K`

**④ 三类陷阱**

| 类型 | 触发方式 | 现象 |
| --- | --- | --- |
| 数组越界 | `buf[8]` 写到 guard | 编译器不报错，灯正常亮，guard 从 `0x11223344` 变成 `0xAAAAAAAA` |
| 悬空指针 | `return &local;` | 编译警告 `-Wreturn-local-addr`；运行时可能读到别人的数据 |
| 野指针 | 指针指向非法地址 | 灯**快闪**（进了 `HardFault_Handler`） |

**⑤ 优化与 UB**

| 代码 | `-O2` 之后 |
| --- | --- |
| `for (int i=0;i<1000;i++){}`（无 volatile） | 整段删除，只剩 `bx lr` |
| `for (volatile int i=0;...)` | 真循环，`movs/str/ldr/cmp/bge` 都在 |
| `__attribute__` / `_Static_assert` | 不产生任何指令 |

| UB | 例子 | 后果 |
| --- | --- | --- |
| 有符号整数溢出 | `INT_MAX + 1` | 打印 `-2147483648`，但 `x+1 > x` 被折成 `1` |
| 整型提升后比较 | `uint8_t i; i <= 255` | 循环永不结束；`-Wextra` 报 `-Wtype-limits` |

**⑥ 整型提升的四个实测数字**

| 表达式 | 结果 | 原因 |
| --- | --- | --- |
| `uint8_t a=200, b=100; a+b` | **300** | 都提升成 `int` 再算 |
| `(uint8_t)(a+b)` | **44** | 300 截断成 8 位 |
| `-1 < 1u` | **0** | `int` 转 `unsigned`，`-1` 变成极大正数 |
| `sizeof(a+b)` | **4** | 结果是 `int` |

## 四、我原来错在哪

> **这一节最值钱。** 标准答案网上都有，自己的弯路只有自己知道。

> ⚠️ **修正 1**：原文写「变量的起始地址默认是 4 的倍数」，实际是「必须是**自身对齐值**的整数倍」。
> `char` 只要 1 的倍数，`int` 要 4 的倍数。本包的几个结构体最大成员都是 `int`，所以看起来都像 4，
> 但换成 `short` 或 `double` 就不一样了。

> ⚠️ **修正 2**：原文写「结构体大小必须是内存**最大变量类型**的整数倍」，更准确是「**最大成员对齐值**」的整数倍。
> 这两者在本包里恰好都等于 4，所以结论对；但 `packed` 结构体里 `int` 的对齐值被压成 1，就不再是 4 了。

**① 以为"写了就会生成指令"**

调 `get_packed(&c1)` 时反汇编里根本没有这段代码。先用局部变量 `cc1` 接返回值、再加 `cc1 += 1`，
以为这样就算"用过了"，结果还是被优化掉。

**真正的原因**：返回值没人用 ⇒ 整个调用没有可观察效果 ⇒ 整段删除。
要调试得加 `__attribute__((noinline))` 防止内联，同时用 `volatile` **全局变量**接收，真正落到内存里才看得见。

**② 以为数组越界会被发现**

`struct box { uint8_t buf[4]; uint32_t guard; }` 里 `guard` 的偏移是 4。
`for (int i = 0; i < 8; i++) g_box.buf[i] = 0xAA;` 写满了 `guard`，值从 `0x11223344` 变 `0xAAAAAAAA`。

**但编译器不报错，程序正常执行，灯还正常亮。** 写 `buf[i]` 时编译器只算地址，不做边界检查。

**③ 以为 RAM 分区是"固定分配"**（最值钱的一条）

原来的理解：链接时给 `.data` / `.bss` 分配固定大小，堆和栈各有一块固定空间，`._user_heap_stack` 只是"剩余共享空间"。

**实际是**：链接时按源码决定 `.data` / `.bss` 的大小；`._user_heap_stack` 只做一件事——**检查** `.data + .bss + 1540` 有没有超过 20K，超了报 `region overflow`。除了静态区，**剩下的全部是堆和栈共享**，两者从两头往中间长，**溢出不会报错，只能自己在运行时检查**（或者干脆不 `malloc`）。
