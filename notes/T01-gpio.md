## 一、最小系统：让芯片跑起来的五个必要部分

| 部分 | 说明 |
|---|---|
| **电源** | 3.3V 供电；接 GND 前加滤波电容，保证电压稳定 |
| **内存** | RAM 20KB / **Flash** 64KB |
| **BOOT** | 选择启动位置，三种模式见下表 |
| **晶振** | 外部 8MHz，经 PLL 倍频到 72MHz，给 CPU 提供心跳 |
| **复位** | 上电时把芯片拉到确定状态，防止卡死 |

**BOOT 三种启动模式**

| BOOT0 | BOOT1 | 从哪里启动 | 用途 |
|---|---|---|---|
| 0 | × | 主闪存（Flash） | 正常运行程序 |
| 1 | 0 | 系统存储器 | 串口下载程序 |
| 1 | 1 | 内置 SRAM | 调试用 |

> ⚠️ **修正 1**：原笔记写「电源在断电后给板子供电」——不对。电源是**提供电能**的；「断电后短暂维持」是**滤波电容**的作用，两者不是一回事。
>
> ⚠️ **修正 2**：原笔记写「ROM 64k」，准确说是 **Flash**。ROM 在 STM32 里通常指系统存储器那部分。

## 二、GPIO

- **输出**：最高 3.3V
- **输入**：大部分引脚是 FT（5V 兼容），但 **PC13/PC14/PC15 不是**，用前查数据手册的引脚表

**两种输出模式**

| 模式 | 行为 | 典型用途 |
|---|---|---|
| **推挽** | 能主动输出高、低电平，驱动能力强 | 驱动 LED、推 MOS 管、输出 PWM |
| **开漏** | **只能主动拉低**，高电平靠外部上拉 | I2C 总线、电平转换 |

> ⚠️ **修正 3（重要）**：原笔记写「开漏输出默认为高」——**这是错的**。
> 开漏输出 1 时，引脚处于**高阻态（悬空）**，不是高电平。没接上拉电阻时，输出 1 等于「放手」，电平由外部电路决定。接了上拉电阻，才在输出 1 时被拉高。
>
> 这个区别要命：配了开漏忘了加上拉，程序写 1 却发现引脚是低电平，会查半天代码——其实是硬件配置问题。

**为什么用开漏**：多设备共享一根线（I2C）时，一个设备拉低，其他设备保持高阻，不会互相短路。

## 三、开时钟流程

RCC 是一个外设模块，它的寄存器里每一位对应一个外设的时钟开关。

用 GPIOC 之前：

```c
RCC->APB2ENR |= (1U << 4);   // bit4 = IOPCEN，打开 GPIOC 时钟
(void)RCC->APB2ENR;          // 读回一次做延迟，确保写操作生效
```

| 端口 | APB2ENR 的位 |
|---|---|
| GPIOA | bit 2 |
| GPIOB | bit 3 |
| GPIOC | bit 4 |
| GPIOD | bit 5 |

> ⚠️ **修正 4**：原笔记写「用 READ_BIT 读写完的结果，同时保证有时间让时钟使能完成」——表述含糊。准确说是**读回一次做延迟（dummy read）**：Cortex-M3 对 APB 外设的写是缓冲的，读一次能确保前面的写已经落到总线上。
>
> 不写这行，紧跟着访问 GPIOC 时可能时钟还没生效——**极其偶发、极难查**的 bug。`__HAL_RCC_GPIOC_CLK_ENABLE()` 这个宏内部就是这么干的。

**不开时钟会怎样**：配置照写、不报错，但外设不执行。现象就是「代码看着没错，灯就是不亮」。

## 四、CRL / CRH：配置引脚

每个端口 16 个引脚，每个引脚占 **4 位**：

| 寄存器 | 管哪几个引脚 |
|---|---|
| **CRL** | pin 0 – 7 |
| **CRH** | pin 8 – **15** |

> ⚠️ **修正 5**：原笔记写「CRH 负责 8–16」，多算了一个。一个端口只有 16 个脚（0–15）。

**4 位的含义：`CNF[1:0]` + `MODE[1:0]`**

| 场景 | MODE[1:0] | CNF[1:0] |
|---|---|---|
| **输入模式** | 决定输入类型 | 00 模拟 / 01 浮空 / 10 上拉或下拉 |
| **输出模式** | 00 慢(2MHz) / 01 中(10MHz) / 10 快(50MHz) | 00 推挽 / 01 开漏 / 10 复用推挽 / 11 复用开漏 |

记忆法：**MODE 管速度（输入时管类型），CNF 管电路形态。**

> ⚠️ **修正 6**：原笔记写「CNF 决定输入模式或输出模式」，不准确。是 **MODE + CNF 共同决定**，不是单靠 CNF。

**PC13 的偏移怎么算**

```
(13 − 8) × 4 = 20   → 占 CRH 的 bit 20–23
```

**推挽输出 2MHz 的值**

```
CNF=00（推挽） + MODE=10（2MHz） = 0b0010 = 0x2
```

**一个关键细节**：`HAL_GPIO_Init` 只配置寄存器，**不设初始电平**。初始化后引脚是什么电平，取决于 ODR 的默认值。

## 五、SysTick 与 HAL_Delay

> ⚠️ **修正 7**：原笔记写「SysTick 硬件每 1ms 溢出」，不准确。SysTick 本身是个 **24 位递减计数器，没有固定 1ms**——是 `HAL_Init()` 按当前主频算出重装值，才配成 1ms 一次的。

**调用链**

```
SysTick 每 1ms 中断
      ↓
SysTick_Handler()          ← 启动文件里是 weak 默认实现（死循环）
      ↓
HAL_IncTick()              ← 让 uwTick 变量 +1
      ↓
HAL_Delay(n)               ← 循环等 uwTick 增加 n 次，才返回
```

**PlatformIO 手写工程必须自己补这段**，否则 `uwTick` 永远不涨，`HAL_Delay` 卡死：

```c
void SysTick_Handler(void)
{
    HAL_IncTick();
}
```

顺带一个以后会踩的坑：**主频从 8MHz 改成 72MHz 但没重新配 SysTick**，`HAL_Delay` 会差 9 倍。

## 六、一开始我以为……后来发现……

> 这一节是整份笔记最值钱的地方——标准答案网上都有，自己的弯路只有自己知道。三个月后复习时，记住的是这里。

### 1. PC13 配推挽能亮，为什么还建议开漏？

**一开始**：能亮就行，所以选了推挽，也没出问题。

**后来发现**：PC13/14/15 在备份域，手册限制 **3mA**，并且明确写「**不能作为电流源（current source）驱动 LED**」。
- 蓝板的 LED 是**低电平点亮**（灌电流），所以推挽**也合规**
- 如果换成「高电平点亮」的接法（引脚向外供电），推挽就违规了
- 官方建议开漏是**防呆**：开漏天生不能作电流源，堵住误接的路

### 2. 「3.3V 过大导致电流过大」？

**一开始**：以为电压高所以电流大，加电阻也没用。

**后来发现**：**电流由电阻决定**，`I = (3.3 − V_LED) / R`。加电阻就是为了限流，选对了推挽也不超限。3mA 是**能力上限**，不是「它会主动输出 3mA」。

### 3. 循环改延时能做呼吸灯吗？

**一开始**：以为把延时值从 10ms 改到 1000ms，就能做出渐亮渐暗。

**后来发现**：亮和灭的延时始终相等 → **占空比恒等于 50% → 亮度根本没变**，只是闪得越来越慢。真正的呼吸灯要用 **PWM 改占空比**，频率固定、亮度渐变。

**一句话记法：亮度看占空比，不看周期。**
