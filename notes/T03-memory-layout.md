## 一、自测（遮住答案先答一遍）

1. `0x2000_4ff4` 和 `0x0800_10f0` 分别属于哪块存储？怎么一眼判断？
2. RAM 从低到高分哪几段？栈为什么在最上面？
3. `uint8_t buf[4096];` 和 `uint8_t buf[4096] = {1};` 分别进哪个段？Flash 变不变？
4. `size` 的 text / data / bss 各装什么？Flash 和 RAM 分别怎么算？
5. 为什么 `data` 要加两次？
6. `((GPIO_TypeDef *)0x40011000)->ODR = 1;` 编译成几条指令？偏移在哪一步算的？
7. `int *p[3]` 和 `int (*p)[3]` 分别是什么？各占几字节？
8. `modes[]` 加不加 `const`，对 RAM 有什么影响？

<details>
<summary>答案（点开对照）</summary>

1. `0x2000_xxxx` → RAM（20KB，`0x2000_0000`~`0x2000_5000`）；`0x0800_xxxx` → Flash（64KB）。**判据只有这一条：地址高半字节**。
2. `.data` → `.bss` → 堆（往上长）→ 空闲 → 栈（从 `0x2000_5000` 往下长）。栈放最上面，是因为它向下生长，从 RAM 末尾开始才有一整片空间可用。
3. 前者 `.bss`（初值 0），**只涨 bss，Flash 不变**；后者 `.data`（有非零初值），**data 涨 4096，text 也涨 4096**（初值要存进 Flash）。
4. text = 向量表 + 代码 + 只读常量；data = 有非零初值的可写全局；bss = 初值 0 的可写全局 **+ 链接器预留的堆栈**。`Flash = text + data`，`RAM = data + bss`。
5. 因为初值存在 Flash，上电时由启动代码拷到 RAM。**同一份数据在两边各有一份**，所以两边的账都要算它。
6. **编译期 2 步 + 运行期 1 条指令**。编译期算 `基址 0x40011000 + ODR 偏移 12`，运行期只有 `str r2, [r3, #12]`——偏移直接编进指令，**运行时没有加法**。
7. `int *p[3]`：数组，3 个 `int*`，占 12 字节。`int (*p)[3]`：指针，指向 `int[3]`，占 4 字节。`[]` 优先级高于 `*`。
8. 不加 `const` → 进 `.data`（占 RAM 12 字节 + Flash 12 字节）；加 `const` → 进 `.rodata`（**只占 Flash**，RAM 省 12 字节）。

</details>

## 二、一句话结论

> **能不能写，决定它在不在 RAM；初值是不是 0，决定它在 data 还是 bss；是不是代码/常量，决定它在不在 text。**

## 三、骨架（表格版）

### 3.1 两块存储

| 区域 | 地址范围 | 掉电 | 放什么 |
| --- | --- | --- | --- |
| Flash | `0x0800_0000` 起，64KB | 不丢 | 向量表、代码、常量、data 初值 |
| RAM | `0x2000_0000` 起，20KB | 丢失 | .data、.bss、堆、栈 |

### 3.2 RAM 从低到高

| 段 | 放什么 | 生长方向 |
| --- | --- | --- |
| `.data` | 有非零初值的全局/静态 | 从低到高排 |
| `.bss` | 初值 0 的全局/静态 | 从低到高排 |
| 堆 | `malloc` 申请的 | 向上 |
| 空闲 | — | — |
| 栈 | **所有函数**的局部变量、参数、返回地址 | **向下**（从 `0x2000_5000` 开始） |

### 3.3 size 三列

| 列 | 组成 | 落在 |
| --- | --- | --- |
| text | 向量表 + 代码 + 只读常量 | 只在 Flash |
| data | 有非零初值的可写数据 | Flash（初值）+ RAM（变量） |
| bss | 初值 0 的可写数据 + **堆栈预留** | 只在 RAM |

`Flash = text + data`　`RAM = data + bss`

### 3.4 小端序

`0x12345678` 在内存里从低地址到高地址是 `78 56 34 12`。
**按字节翻，不按半字节翻**：1 字节 = 8 bit = 2 位十六进制，所以一组永远是两位。

## 四、我原来错在哪

> ⚠️ **修正 1**：把 `text` 写成了 `test`（原文 3 处）。**`text` 是代码段的名字**，跟"测试"无关，也与你变量 `test` 无关——这个名字来自 Unix 的 "text segment"（正文段）。写成 test 复习时会和变量混淆。

> ⚠️ **修正 2**：原文「栈中存放的是主函数里面的局部变量」——**不只是主函数**。所有函数的局部变量、函数参数、返回地址都在栈上；调用一层压一层，这就是"栈"这个名字的由来。

> ⚠️ **修正 3**：原文「数组越界后不会报错，但是可能会用在其他变量的地址上」——表述不清。准确说法：**越界会写到相邻变量的内存上**（`g_buf[16]` 正好落在 `g_test[0]`），不报错、不崩溃，只是悄悄改掉别人。

> ⚠️ **修正 4**：`volatile` 那条被截断了。补完：告诉编译器这个值可能被**程序之外**的因素改变（中断、硬件），每次访问都必须真正读写内存，**不许缓存到寄存器、不许合并或删除**。

> ⚠️ **修正 5**：原文「C 语言不允许函数数组」——更准确的说法是：**函数类型不能作为数组元素，函数指针可以**。所以只能写 `void (*arr[3])(void)`，写不出 `void arr[3](void)`。

> ⚠️ **修正 6**：函数指针那条最后没写完（"代码写 modes[0] 的时候……"）。补完：`modes[0]` 是**函数指针**，`modes[0]()` 才是**调用**；直接写 `modes[0]` 只是取到地址，不会执行。

### volatile 的经典翻车场景

```c
/* 错：等标志位，编译器认为 flags 不会变，只读一次 */
while (flags == 0) { }
```

不加 `volatile` 时，GCC 会把 `flags` 读进寄存器，然后**死循环永远不退出**——因为循环体里没有任何代码会改它，优化器认为没必要重复读。
加了 `volatile` 才每次都真去内存读，中断里改的值才能被看见。
**HAL 里所有寄存器指针都是 `volatile`，就是这个原因。**

## 七、三句话（10-30 补记）

这三条是自测之后补进来的，分别对应自测第 1、2、4 题，也是我原来最容易混的地方。

> **① 段的归属在编译期就定死了，运行时怎么赋值都改不了它。**
>
> 判据只有一个：**源码里有没有静态初值**。
> `static uint8_t a[10];` → 没初值 → `.bss`，编译期就定了。
> `a[10] = 0xFF;` → 这是**运行期写内存**的一条 `strb` 指令，跟"给 a 加初值"毫无关系。
>
> 所以"运行时赋过值所以进 .data"这个想法是错的。`.data` 只认**写在源码里的初值**。

> **② 强转改变的是"读几个字节"的规则，地址没变。**
>
> ```c
> uint32_t x = 0x11223344;
> *(uint8_t *)&x    /* → 0x44，只读 1 个字节，正好是最低字节 */
> ```
>
> `uint8_t *` 和 `uint32_t *` 指向同一个地址，区别只在"读几个字节、怎么解释"。
> ⚠️ 配套的坑：`x/8xb &x` 会显示 **8 个字节**，其中只有前 4 个属于 `x`，后 4 个是邻居或残留。

> **③ 栈溢出不一定立刻崩。**
>
> 可能只是踩坏相邻变量（现象是"改了个不相干的东西，另一个变量莫名变了"），也可能踩到返回地址直接 HardFault。
> **`size` 永远看不见**——它只统计静态分配，栈是运行时才真正使用的。所以"size 没超"不等于"不会崩"。

### 附：一个能说明 ① 和 ③ 的实测

```c
static uint8_t  a[10];   /* +0x00，10 字节 */
                         /* +0x0A ~ +0x0B，2 字节对齐填充 */
static uint32_t b;       /* +0x0C */
```

`a[10] = 0xFF` 编译成 `strb r1, [r3, #10]`，正好落在填充里 → **`b` 一点没变**。
把 `a` 改成 `a[12]`，`b` 就紧跟 `+12`，`a[12]` 写的就是 `b` 的最低字节 → `b` 变成 `0x000000FF`。

**越界有没有后果，取决于链接器把它排在哪儿。**
